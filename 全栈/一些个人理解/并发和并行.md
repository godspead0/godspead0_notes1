# 并发（Concurrency）与并行（Parallelism）：核心区别与实战理解

并发和并行是编程中处理多任务的核心概念，很多开发者容易混淆——**并发是“多任务交替执行”（看起来同时），并行是“多任务同时执行”（真正同时）**。下面用生活化例子+技术场景，帮你彻底分清：

## 一、先看生活化例子（秒懂核心差异）

### 场景：完成3件事——煮开水、切菜、炒菜

#### 1. 并发（Concurrency）：一个人“轮流做”多件事

你只有一个人（相当于**单核心CPU**），无法同时做3件事，但可以通过“交替切换”提高效率：

- 第一步：点燃燃气灶煮开水（启动任务A），然后不用等水开，转身去切菜（切换到任务B）；
- 第二步：切了30秒菜，回头看水快开了，关火（结束任务A），再去炒菜（切换到任务C）。

**核心特点**：任务不是同时进行，而是“快速交替”，从宏观上看像“同时在做”，本质是“时间片复用”。

#### 2. 并行（Parallelism）：多个人“同时做”多件事

你和家人共3个人（相当于**多核CPU**），每人负责一件事：

- 你：煮开水（任务A）；
- 家人1：切菜（任务B）；
- 家人2：炒菜（任务C）。

**核心特点**：多个任务在同一时刻真正同时进行，必须依赖“多个独立资源”（多个人、多核CPU）。

## 二、技术定义与核心对比（表格清晰呈现）

| 对比维度     | 并发（Concurrency）                                          | 并行（Parallelism）                                          |
| ------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **核心定义** | 多任务在**同一时间段内**交替执行（宏观同时，微观交替）       | 多任务在**同一时刻**同时执行（宏观+微观都同时）              |
| **依赖资源** | 可依赖单核心CPU（通过任务切换实现）                          | 必须依赖多核心CPU/多服务器（多个独立执行单元）               |
| **核心目标** | 提高单资源的利用率（避免等待，比如IO等待时切换任务）         | 提高整体任务的执行速度（同时处理多个任务）                   |
| **典型场景** | - 单核心CPU运行多线程；<br>- 后端处理高并发请求（如Tomcat的线程池）；<br>- 异步IO（如Node.js的事件循环） | - 多核CPU运行多线程；<br>- 大数据计算（如Spark的并行计算）；<br>- 集群中的负载均衡（多服务器并行处理请求） |
| **实现方式** | 线程切换、进程切换、异步编程（回调、Promise、协程）          | 多线程（绑定不同CPU核心）、多进程、分布式集群                |
| **关键问题** | 线程安全（竞态条件、死锁）、上下文切换开销                   | 资源分配、任务拆分与合并、分布式一致性                       |

## 三、编程中的实际例子（C++代码演示）

### 1. 并发示例：单核心下的多线程交替执行

单核心CPU中，多线程通过操作系统的“时间片轮转”实现并发——每个线程执行一小段时间（比如10ms），然后切换到下一个线程，宏观上看起来“同时运行”。

```C++
#include <iostream>
#include <thread>
#include <chrono>
using namespace std;

// 任务1：打印数字
void printNumbers() {
    for (int i = 1; i <= 5; ++i) {
        cout << "数字：" << i << endl;
        this_thread::sleep_for(chrono::milliseconds(100)); // 模拟任务执行时间
    }
}

// 任务2：打印字母
void printLetters() {
    for (char c = 'A'; c <= 'E'; ++c) {
        cout << "字母：" << c << endl;
        this_thread::sleep_for(chrono::milliseconds(100));
    }
}

int main() {
    // 创建两个线程（单核心CPU下交替执行，并发）
    thread t1(printNumbers);
    thread t2(printLetters);

    t1.join();
    t2.join();
    return 0;
}
```

**执行结果（交替输出，体现并发）**：

```Plain
数字：1
字母：A
数字：2
字母：B
数字：3
字母：C
...
```

### 2. 并行示例：多核CPU下的多线程同时执行

如果你的电脑是多核CPU（比如4核），上面的代码会真正“同时执行”——`t1`绑定到CPU核心1，`t2`绑定到CPU核心2，两个线程在同一时刻运行，执行速度更快。

**关键补充**：C++中可以通过`std::thread::hardware_concurrency()`获取CPU核心数，判断是否支持并行：

```C++
cout << "CPU核心数：" << thread::hardware_concurrency() << endl; // 输出当前CPU核心数
```

## 四、常见误区澄清（避免踩坑）

### 误区1：“多线程=并行”

错！多线程是否并行，取决于CPU核心数：

- 单核心CPU：多线程是**并发**（交替执行）；
- 多核CPU：多线程可以是**并行**（不同核心同时执行）。

### 误区2：“并发比并行效率高”

不一定：

- 并发适合“有等待时间的任务”（如IO操作、网络请求）——比如后端处理请求时，一个线程等待数据库响应，同时切换到另一个线程处理新请求，提高CPU利用率；
- 并行适合“CPU密集型任务”（如数学计算、大数据处理）——比如用多核心同时计算多个数据块，减少总耗时。

### 误区3：“异步编程是并行”

错！异步编程是**并发**的一种实现方式，不依赖多核心：

- 比如Node.js是单线程，但通过“事件循环”处理异步IO（如文件读取、网络请求）——在等待IO响应时，不阻塞线程，继续处理其他任务，本质是“单线程并发”，不是并行。

## 五、核心总结（一句话记住）

- **并发**：“一个人同时处理多件事”——通过任务切换提高资源利用率，解决“任务多但资源少”的问题；
- **并行**：“多个人同时处理多件事”——通过增加资源（多核、多服务器）提高处理速度，解决“任务多且资源足够”的问题；
- 口诀：**并发是“轮流做”，并行是“同时做”**。

在实际开发中，并发常用于处理高并发请求（如Web后端），并行常用于CPU密集型计算（如大数据、AI），两者也可结合使用（如多核CPU下的多线程并发+并行）。
