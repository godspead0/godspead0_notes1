# 敏捷开发在 Spring Boot 项目中的 Scrum 应用

敏捷开发是一种**以人为核心、迭代式、增量式**的软件开发方法论，核心目标是**快速响应需求变化、持续交付有价值的软件**，而非僵化遵循预先制定的全量计划。它是对传统“瀑布模型”的革新，特别适合需求多变、团队协作紧密的现代软件开发场景（比如你正在做的Spring Boot全栈项目）。

## 一、敏捷开发的核心思想：《敏捷宣言》

2001年，17位软件开发者提出《敏捷软件开发宣言》，奠定了敏捷的核心原则，核心是**四大价值对比**：

1. **个体和互动** 高于 流程和工具
2. **可用的软件** 高于 详尽的文档
3. **客户协作** 高于 合同谈判
4. **响应变化** 高于 遵循计划

简单来说：敏捷不排斥流程/文档/计划，而是强调**“能跑的代码比厚厚的文档更重要”“需求变了就快速调整，而非死守原计划”**。

## 二、敏捷开发的核心特点

1. **迭代式开发**

1. 将整个项目拆分成多个**短周期的迭代（Sprint）**，每个迭代通常2-4周，最终交付一个**可独立运行的增量功能**。

1. 比如开发电商后端：

    - 迭代1：完成用户注册/登录接口
    - 迭代2：完成商品列表/详情接口
    - 迭代3：完成购物车功能

     每个迭代结束都能交付可用功能，而非等全部开发完才交付。

1. **增量式交付**

1. 功能不是一次性全部完成，而是**逐步叠加**。迭代过程中可以随时根据用户反馈调整需求，避免最后交付的产品和用户预期不符。

1. **团队自组织协作**

1. 敏捷团队没有严格的“上下级”，而是由开发者、测试、产品经理等角色组成跨职能团队，共同对迭代结果负责。

1. 比如每日站会同步进度，遇到问题快速协作解决，而非层层汇报。

1. **持续反馈与改进**

1. 每个迭代结束后会开**回顾会议**，团队复盘“这次迭代哪里做得好、哪里可以改进”，比如“下次缩短需求评审时间”“优化接口测试流程”，形成持续改进的闭环。

## 三、敏捷开发的常见落地框架

敏捷是一种**思想**，而框架是敏捷思想的**具体实现方式**，最常用的有2种：

### 1. Scrum（最主流）

Scrum是敏捷中最易落地的框架，核心角色、事件、工件都有明确定义：

| 核心要素     | 具体内容                                                     |
| ------------ | ------------------------------------------------------------ |
| **核心角色** | 1. **产品负责人（PO）**：确定需求优先级，维护「产品待办列表」<br>2. **Scrum Master**：保障团队按Scrum规则运行，解决阻碍<br>3. **开发团队**：跨职能（开发、测试、前端/后端），自组织完成迭代任务 |
| **核心事件** | 1. **Sprint计划会**：迭代开始前，确定本次迭代要完成的任务<br>2. **每日站会**：每天15分钟，团队同步3件事：昨天做了啥、今天要做啥、遇到啥阻碍<br>3. **Sprint评审会**：迭代结束后，向产品负责人演示可运行的功能，获取反馈<br>4. **Sprint回顾会**：团队复盘迭代过程，提出改进措施 |
| **核心工件** | 1. **产品待办列表（Product Backlog）**：所有需求的清单，按优先级排序<br>2. **Sprint待办列表（Sprint Backlog）**：本次迭代要完成的需求子集<br>3. **增量（Increment）**：迭代结束交付的可用软件功能 |

### 2. Kanban（看板）

看板的核心是**可视化工作流**，通过看板（比如Trello、Jira的看板）直观展示任务状态，核心规则：

- 任务分为「待办」「进行中」「测试中」「已完成」等状态列
- 限制「进行中」的任务数量（比如最多同时进行3个），避免团队并行任务过多导致效率下降
- 任务从左到右流动，直到完成
- 适合需求变化极快、不需要固定迭代周期的场景（比如运维、紧急bug修复）

### 3. 其他框架

- **XP（极限编程）**：强调“高质量代码”，核心实践包括**结对编程**（两人一台电脑写代码）、**测试驱动开发（TDD）**（先写测试用例，再写功能代码）、**持续集成**（代码频繁合并到主干，自动测试）。
- **精益开发**：源于制造业，核心是“消除浪费”，比如减少不必要的文档、避免做用户不需要的功能。

## 四、敏捷开发 vs 传统瀑布模型

| 维度     | 敏捷开发                                 | 瀑布模型                                       |
| -------- | ---------------------------------------- | ---------------------------------------------- |
| 开发方式 | 迭代式、增量式                           | 线性阶段式（需求→设计→开发→测试→部署，不可逆） |
| 需求处理 | 允许需求中途变化，快速响应               | 需求一旦确定，中途不允许修改                   |
| 交付方式 | 迭代结束交付可用功能                     | 项目全部完成后一次性交付                       |
| 团队协作 | 跨职能自组织团队，紧密协作               | 按职能分工（开发、测试分开），层层汇报         |
| 适用场景 | 需求多变的项目（如互联网产品、创业项目） | 需求明确的项目（如政府项目、桥梁工程软件）     |

## 五、敏捷开发在Spring Boot项目中的实际应用

以你搭建的Spring Boot + Vue全栈项目为例，敏捷实践可以这样落地：

1. **定义MVP（最小可行产品）**：先确定核心需求——用户注册登录、商品展示、下单，作为第一个迭代的增量。
2. **2周一个Sprint**：迭代1完成后端接口+前端基础页面，迭代2完成购物车+支付功能，迭代3完成订单管理+用户中心。
3. **每日站会**：每天花15分钟同步进度，比如“我昨天完成了用户登录接口，今天要写商品列表接口，遇到了跨域问题需要前端配合”。
4. **持续集成/交付**：用Git管理代码，每次提交自动触发单元测试（比如JUnit测试），测试通过后自动部署到测试环境，供前端联调。
5. **迭代回顾**：迭代结束后，复盘“接口文档写得太简略导致前端联调慢”，下次改进为“每个接口都写好Swagger注释”。

2. Scrum是最常用的落地框架，通过固定迭代周期、可视化流程保障团队效率。
3. 敏捷适合需求多变的互联网项目，而你正在做的Spring Boot全栈项目，正是敏捷的典型适用场景。
4. 敏捷的核心不是“没有计划”，而是“计划可以灵活调整”，最终目标是**更快地交付用户真正需要的软件**。
