你想了解的`volatile`是 Java 中的核心关键字，`DCL`（Double-Checked Locking，双重检查锁定）是一种**基于 volatile 实现的设计模式**，二者在**单例模式**中结合得最为紧密，核心解决多线程环境下的**变量可见性**和**对象初始化安全**问题。

下面我会从**概念、核心作用、使用场景**三个维度，先讲`volatile`，再讲`DCL`，最后结合代码说明二者的关联，内容通俗易懂，贴合 Java 开发的实际使用场景。

### 一、volatile 关键字

`volatile`是 Java 提供的**轻量级同步机制**，只能修饰**成员变量 / 静态成员变量**，不能修饰方法、类，它不保证原子性，但能解决多线程下的**内存可见性**和**指令重排**问题，是比`synchronized`更轻量的同步方案（无锁竞争，性能损耗极小）。

#### 1. 核心特性 1：保证变量的**内存可见性**

首先要理解 Java 的**内存模型（JMM）** 基础：多线程访问共享变量时，不会直接操作**主内存**的变量，而是先把主内存的变量**拷贝到自己的工作内存**，修改后再刷回主内存。

- 普通共享变量：线程修改后，可能不会**立即刷回主内存**，其他线程读取的还是自己工作内存中的旧值，这就是**内存不可见**问题。
- volatile 修饰的变量：强制线程**修改后立即刷回主内存**，**读取时直接从主内存加载**，保证所有线程看到的变量值都是最新的，解决可见性问题。

#### 2. 核心特性 2：**禁止指令重排**

编译器和 CPU 为了优化程序执行效率，会在**不改变单线程执行结果**的前提下，对代码的执行顺序进行**重排**（指令重排），这在单线程中没问题，但**多线程中会导致执行逻辑混乱**。

- volatile 修饰的变量，会通过**内存屏障**（一种 CPU 指令）阻止编译器和 CPU 对其相关的代码进行指令重排，保证代码的**执行顺序与编写顺序一致**。

#### 3. 重要注意点：**不保证原子性**

原子性指 “一个操作要么全部执行完成，要么不执行，中间不会被打断”。

volatile**无法保证复合操作的原子性**，比如`i++`（实际是`读i→i+1→写i`三步操作），多线程执行时仍会出现线程安全问题（需要配合`synchronized`或`AtomicInteger`解决）。

#### volatile 简单使用示例

java



运行









```
public class VolatileDemo {
    // 用volatile修饰共享变量，保证可见性和禁止指令重排
    private volatile boolean flag = false;

    // 线程1修改flag
    public void setFlag() {
        this.flag = true;
    }

    // 线程2读取flag，保证能立即看到线程1的修改
    public void getFlag() {
        while (!flag) {
            // 若无volatile，线程2可能一直读到false，进入死循环
        }
        System.out.println("flag被修改为true，循环退出");
    }
}
```

### 二、DCL（Double-Checked Locking）双重检查锁定

DCL 是一种**多线程环境下的优化设计模式**，**核心用于单例模式**，解决了**懒汉式单例**的两个痛点：

1. 普通懒汉式加`synchronized`在方法上，**每次调用都加锁**，性能损耗大；
2. 多线程下，单重检查会导致**重复创建单例对象**，线程不安全。

DCL 的核心思想：**两次检查单例对象是否为 null，仅在对象未创建时加锁**，既保证线程安全，又避免了频繁加锁的性能损耗，**但 DCL 必须配合 volatile 使用**，否则会出现**半初始化对象**问题。

#### 1. 为什么需要 “双重检查”？

假设只有**一次检查**，多线程场景下会出现如下问题：

java



运行









```
// 错误的单重检查懒汉式
public class Singleton {
    private static Singleton instance;
    private Singleton() {} // 私有构造，禁止外部new

    public static Singleton getInstance() {
        if (instance == null) { // 单重检查
            synchronized (Singleton.class) { // 加锁
                instance = new Singleton(); // 多线程会重复创建
            }
        }
        return instance;
    }
}
```

- 线程 A 和线程 B 同时走到`if (instance == null)`，都判断为 null；
- 线程 A 先拿到锁，创建对象后释放锁；
- 线程 B 拿到锁后，不会再检查，直接再次创建对象，导致单例失效。

**双重检查**就是在**加锁后再做一次 null 判断**，阻止后续线程重复创建对象。

#### 2. 为什么 DCL 必须配合 volatile？

核心原因：**对象的实例化过程不是原子操作**，编译器会对其进行**指令重排**，如果没有 volatile 禁止重排，会产生**半初始化对象**（引用非 null，但对象属性还没初始化完成）。

##### 步骤 1：对象实例化的 3 个核心步骤

`instance = new Singleton()` 看似一行代码，实际分为 3 步执行：

1. **分配内存空间**：给 Singleton 对象分配内存；
2. **初始化对象**：执行 Singleton 的构造方法，初始化成员变量；
3. **引用指向内存**：将 instance 引用指向刚分配的内存地址（此时 instance != null）。

##### 步骤 2：指令重排的问题

编译器为了优化，可能会将**步骤 2 和步骤 3 重排**，执行顺序变为：`1→3→2`。

- 线程 A 执行`1→3`后，还没执行`2`（对象未初始化，半初始化状态），此时 instance != null；
- 线程 B 走到第一次`if (instance == null)`，发现 instance != null，直接返回这个**半初始化的对象**；
- 线程 B 使用该对象时，会出现**空指针异常**或**属性值错误**。

##### 步骤 3：volatile 的解决作用

volatile 的**禁止指令重排**特性，会强制保证实例化的 3 步按`1→2→3`的顺序执行，只有对象**完全初始化完成**后，instance 引用才会被赋值为非 null，从根本上避免半初始化对象问题。

### 三、DCL+volatile 实现**线程安全、高性能、懒加载**的单例（最终正确版）

这是 Java 中**最推荐的单例实现方式**，结合了懒加载（用到时才创建）、线程安全、高性能（仅第一次创建时加锁）的优点，代码如下：

java



运行









```
public class SingletonDCL {
    // 关键：用volatile修饰单例引用，禁止指令重排
    private static volatile SingletonDCL instance;

    // 私有构造方法，禁止外部通过new创建对象
    private SingletonDCL() {}

    // DCL核心方法：双重检查+加锁
    public static SingletonDCL getInstance() {
        // 第一次检查：对象已创建则直接返回，避免频繁加锁，提升性能
        if (instance == null) {
            // 类对象加锁，保证多线程下只有一个线程能进入
            synchronized (SingletonDCL.class) {
                // 第二次检查：防止多线程等待锁后重复创建对象
                if (instance == null) {
                    instance = new SingletonDCL(); // 实例化对象
                }
            }
        }
        return instance;
    }
}
```

#### 代码执行逻辑（多线程场景）

1. 多个线程同时调用`getInstance()`，第一次检查`instance == null`，只有空时才会进入加锁逻辑；
2. 第一个线程拿到锁，第二次检查仍为 null，创建对象后释放锁；
3. 其他线程拿到锁后，第二次检查发现`instance != null`，直接释放锁并返回对象；
4. 后续所有线程调用`getInstance()`，第一次检查就会发现对象已存在，直接返回，无需加锁。

### 四、volatile 和 DCL 的核心关联

1. `volatile`是 DCL 的**基础保障**：没有 volatile 的禁止指令重排特性，DCL 会出现半初始化对象问题，线程不安全；
2. DCL 是 volatile 的**典型应用场景**：volatile 的禁止指令重排特性，在 DCL 单例中体现得最直观、最常用；
3. 二者结合实现**性能与安全的平衡**：volatile 轻量保证初始化顺序，DCL 双重检查避免频繁加锁，比直接在方法上加`synchronized`的懒汉式性能提升极大。

### 总结

1. **volatile**：Java 轻量级同步关键字，仅修饰变量，核心作用是**保证内存可见性**、**禁止指令重排**，**不保证原子性**，无锁竞争，性能损耗极小；
2. **DCL**：双重检查锁定，是一种多线程优化模式，核心用于单例模式，通过**两次 null 检查 + 一次加锁**，解决懒汉式单例的线程安全和性能问题；
3. **核心关联**：DCL 必须配合 volatile 使用，否则对象实例化的指令重排会导致**半初始化对象**，引发线程安全问题，二者结合是 Java 中最优的懒加载单例实现方案。
