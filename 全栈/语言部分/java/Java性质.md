#### 易错点

1. Java不允许在类声明中直接写可执行代码，必须将代码放在方法、构造器或静态初始化块中
2. Java是一门强类型的编程语言，定义变量时必须声明类型，赋值时必须赋予和变量类型一样的值
3. 构造方法必须与类同名，成员方法可以与类同名
4. 构造方法在一个对象被new时会自动执行
5. GC：程序员无法强制GC执行，GC仅能回收无用内存，GC线程优先级低，对象设置null需等GC下次执行才回收
6. 赋值表达式的返回值是被赋值的变量的类型
7. sleep是静态方法，不存在实例，不能用this.sleep（），只能用Thread.sleep（）；sleep方法接收的参数为long类型；且该方法只能控制当前线程的休眠，不能控制其他线程
8. 随机数生成：静态方法Math.random（），（int）Math.random（）* 100为0~99的随机数
9. 标识符不能由数字开头
10. static不能修饰局部变量，静态内部类只能访问外部类的静态成员
11. 外部类的访问权限只能是public或default；局部成员是没有访问控制权限的
12. 构造方法前不能由任何返回值声明，且不能用return返回一个值
13. this和super调用构造方法是必须放第一行，且不能同时出现，成员方法不允许调用本类的构造函数，可以调用内部类的
14. 构造块优先于构造方法执行，执行顺序：静态代码块--构造快--构造方法
15. 静态方法只能访问静态成员，因为可能出现静态方法在执行时，相关的非静态成员还未被创建
16. 子类中重写的方法需要和父类中被重写的方法具有相同的方法名、参数列表以及返回值类型
17. 子类重写父类方法时，不能使用比父类的方法更严格的访问权限
18. 抽象类不一定有抽象方法
19. instanceof：基本类型无法使用，左边必须是引用类型，右边必须是类、接口、数组类型，适用多层继承关系（boolean isIntArray = obj1 instanceof int[];）
20. String类型对象相同的判断条件只有==，String会重写hashCode方法，使其返回值是根据字符串的内容（字符序列）计算的，而不是根据对象的内存地址
21. throw使用时需要有throws或者try
22. try(){}-catch(){}会自动释放资源
23. String对象创建后不能修改值，只能修改其指向的字符串
24. 时间戳是从1970年1月1日0时0分0秒开始计算
25. toString是返回String类型的值
26. 出Character外的包装类都有valueOf(String s)方法和parseXxx(String s)静态方法；valueOf(String s)是用来创建包装类的，其中s必须可以解析为对应的基本类型；parseXxx(String s)是将对应的字符串对象转换为对应的基本类型数据
27. Map不是Collection的子类，Collection是所有单列集合的父类
28. 使用Iterator对集合进行遍历时，如果使用remove（）删除元素，会出现异常
29. foreach循环不能改变数组中元素的值
30. Map中键的值是唯一的，后续有相同的键出现则会将原来的值覆盖
31. 使用非泛型类实现泛型接口时，需要明确接口的泛型类型，也就是需要将类型实参传入接口，此时该类只能接收一种类型；而使用泛型类实现泛型接口则只需要确保泛型类和泛型接口的类型形参是同一个就行了，此时该类可以接收任意类型
32. 泛型中的类名和泛型的声明是一个整体类型，例：Person<Object>不是Person<String>的父类
33. 设置上限：<? extends 类>；设置下限：<? super 类>
34. File是java.io包中唯一一个可以代表磁盘文件的对象
35. FilenameFilter接口是文件过滤器，可使用匿名内部类，需实现accept方法；endsWith（）用于识别扩展名
36. BufferedInputStream的直接父类不是InputStream也不是FileInputStream而是FilterInputStream；BufferedReader的直接父类是Reader
37. 字符流中的read（）方法括号里不加参数返回的是字符的Unicode码，加参数（字符数组）则返回接收的字符数，到末尾时返回-1
38. 一个单核CPU同一时刻只能处理一个进程；每一个进程至少有一个线程
39. 当进程中不存在前台线程时，整个进程就会结束；使用setDeamon方法设置后台线程时，该方法必须在start之前，否则设置无效
40. 线程在可运行状态不一定开始运行了，需要获得CPU的使用权
41. 设计多线程应用时，其功能实现不能依赖线程的优先级，只能使用线程的优先级提高效率
42. interrupt（）线程中断方法；isInterrupted（）获取并清除当前线程的标志位，返回值为boolean，在线程未启动时调用interrupt方法后在调用isInterrupted方法的返回值为false，即未启动，不可能中断，不需要清除标志位
43. currentThread（）静态方法，返回当前正在执行的线程对象的引用
44. 同步代码块中的锁对象可以是任意类型的对象，但多个线程共享的锁对象必须是同一个
45. 同步方法的锁：普通方法是调用该方法的对象，即this指向的对象；静态方法则是该方法所在类的class对象，class对象在装载该类时自动创建，直接用类名.class获取
46. 重入锁加了几把就要释放几把
47. Java虚拟机默认的线程调度模型是抢占式调度模型

#### Error和Exception

|              | Error                                                        | Exception                                                    |
| ------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 继承结构     | 继承自 `Throwable` 类                                        | 继承自 `Throwable` 类                                        |
| 含义         | 表示严重的、不可恢复的系统错误，通常由 JVM 或底层系统问题导致 | 表示程序运行过程中可被捕获和处理的异常情况                   |
| 是否可恢复   | 不可恢复                                                     | 部分可恢复，通过适当的异常处理代码可使程序继续运行或进行错误处理 |
| 处理方式     | 应用程序不应该尝试捕获和处理，即使捕获也难以有效恢复         | 分为受检异常和非受检异常。受检异常必须在代码中显式捕获处理或声明抛出；非受检异常可不显式处理，但通常应改进程序逻辑避免 |
| 对程序的影响 | 通常导致程序终止                                             | 受检异常若不处理会导致编译错误；非受检异常在运行时抛出，可能导致程序崩溃，但可通过异常处理机制增强程序健壮性 |

#### 静态方法和成员方法

| 比较项   | 静态方法                                                     | 成员方法                                                     |
| -------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 定义     | 使用 `static` 关键字修饰的方法                               | 没有 `static` 关键字修饰，属于类实例的方法                   |
| 调用方式 | 可通过类名直接调用，例如 `ClassName.staticMethod();`，也可通过对象调用，但不推荐 | 必须通过类的实例（对象）来调用，例如 `ObjectInstance.memberMethod();` |
| 访问限制 | 只能访问静态成员（静态变量和静态方法），不能直接访问非静态成员 | 可以访问类中的所有成员，包括静态和非静态的变量与方法         |
| 内存分配 | 类加载时分配内存，在方法区中只有一份实例，为所有类的对象共享 | 对象创建时，在堆内存中为每个对象的成员方法分配入口地址，不同对象的成员方法逻辑相同，但属于不同对象实例 |
| 多态性   | 不支持多态特性。调用静态方法时，根据调用的类名确定执行的方法，而非根据对象的实际类型 | 支持多态特性。运行时根据对象的实际类型来决定执行哪个类中的方法 |
| 生命周期 | 随着类的加载而存在，随着类的卸载而消失                       | 随着对象的创建而存在，随着对象的销毁而消失                   |
| 使用场景 | 常用于工具类中，提供一些与类相关但不依赖于特定对象状态的通用功能，例如 `Math.sqrt()`；或用于对静态数据进行操作 | 用于处理与对象的状态（成员变量）相关的业务逻辑，不同对象调用可能产生不同结果 |

#### 面向对象的三大特征

| 特征     | 简述                                                         |
| -------- | ------------------------------------------------------------ |
| **封装** | 将对象的属性和行为看成一个密不可分的整体；将数据和操作封装在类中，通过访问修饰符控制外部对内部成员的访问，实现数据隐藏与保护，提升代码安全性与可维护性。 |
| **继承** | 子类继承父类的属性和方法，可复用父类代码，构建类的层次结构，体现一般与特殊关系，便于代码扩展与维护。 |
| **多态** | 同一操作作用于不同对象产生不同结果，通过继承和方法重写实现，运行时依据对象实际类型确定执行的方法，增强代码灵活性与通用性。 |

#### 基本数据类型和包装类

| 比较项              | 基本数据类型                                                 | 包装类                                                       |
| ------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **定义**            | Java 中内置的、最基础的数据类型，用于存储简单的数据值        | 为基本数据类型提供的对应的类，将基本数据类型包装成对象，以满足面向对象编程的需求 |
| **数据类型**        | 8 种基本数据类型：`byte`、`short`、`int`、`long`、`float`、`double`、`char`、`boolean` | 与基本数据类型对应的 8 个包装类：`Byte`、`Short`、`Integer`、`Long`、`Float`、`Double`、`Character`、`Boolean` |
| **内存存储**        | 存储在栈内存（除 `double` 和 `long` 可能存储在堆内存，取决于具体实现），直接存储数据值 | 对象存储在堆内存，对象中包含对应的基本数据类型的值           |
| **默认值**          | `byte`、`short`、`int`、`long` 默认值为 `0`；`float`、`double` 默认值为 `0.0`；`char` 默认值为 `'\u0000'`；`boolean` 默认值为 `false` | `Byte`、`Short`、`Integer`、`Long`、`Float`、`Double` 默认值为 `null`；`Character` 默认值为 `null`；`Boolean` 默认值为 `null` |
| **可变性**          | 基本数据类型的值是不可变的，当对其赋值新值时，原有的值会被覆盖 | 包装类对象一旦创建，其值也是不可变的。例如 `Integer` 对象，对其执行算术运算等操作会返回新的 `Integer` 对象 |
| **功能方法**        | 本身不具备方法，仅能进行基本的算术运算、逻辑运算等操作       | 提供了丰富的方法，例如 `Integer` 类有 `parseInt` 方法用于将字符串转换为整数，`compareTo` 方法用于比较两个 `Integer` 对象的值等；`Character` 类有判断字符类型的方法，如 `isDigit`、`isLetter` 等 |
| **使用场景**        | 在大量数据运算、性能要求较高的场景下使用，因为其占用内存小、处理速度快 | 在需要使用对象的场景下使用，如泛型中只能使用包装类；集合框架中存储数据也需使用包装类；还可利用包装类提供的各种实用方法 |
| **自动装箱 / 拆箱** | -                                                            | JDK 1.5 引入自动装箱（将基本数据类型自动转换为包装类对象）和拆箱（将包装类对象自动转换为基本数据类型）机制。例如 `Integer i = 10;`（自动装箱），`int j = i;`（自动拆箱） |

#### 重载和重写

| 比较项         | 重载（Overloading）                                          | 重写（Overriding）                                           |
| -------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **定义**       | 在同一个类中，允许存在多个同名方法，但这些方法的参数列表（参数个数、类型或顺序）不同 | 子类中定义的方法与父类中某个方法具有相同的方法名、参数列表和返回类型（或是返回类型的子类型，在 Java 5.0 及之后版本支持） |
| **发生范围**   | 发生在同一个类中                                             | 发生在具有继承关系的子类与父类之间                           |
| **参数列表**   | 必须不同                                                     | 必须与父类被重写方法相同                                     |
| **返回类型**   | 可以不同，但需遵循与参数列表共同构成有效重载的规则           | 与父类被重写方法相同，或是返回类型的子类型（协变返回类型）   |
| **访问修饰符** | 无限制，可根据需求定义不同访问修饰符                         | 子类重写方法的访问修饰符不能比父类被重写方法的访问修饰符更严格（例如父类方法为 `protected`，子类重写方法不能为 `private`） |
| **异常抛出**   | 无限制，可根据方法逻辑抛出不同类型和数量的异常               | 子类重写方法抛出的异常不能比父类被重写方法抛出的异常更宽泛，即可以抛出更少或更具体的异常，或者不抛出异常 |
| **多态性体现** | 编译时多态（静态多态），在编译阶段，编译器根据调用方法时传入的参数类型和数量来决定调用哪个重载方法 | 运行时多态（动态多态），在运行阶段，根据对象的实际类型来决定调用哪个类中的重写方法 |
| **作用**       | 提高代码的可读性和复用性，通过相同方法名不同参数列表来实现相似功能的不同操作 | 实现对父类方法的扩展或修改，使得子类能够根据自身需求定制化实现从父类继承的方法 |

#### 书写顺序

1. **限制访问权限修饰符**：`public`、`protected`、`private` 或包访问权限（即不写修饰符），用于控制方法的访问范围。
2. **其他修饰符**：
   - `abstract`：表示该方法是抽象方法，没有方法体，必须在抽象类中声明。
   - `static`：表示该方法是静态方法，属于类而不是类的实例，可以通过类名直接调用。
   - `final`：表示该方法不能被子类重写。
   - `synchronized`：用于多线程编程，确保同一时间只有一个线程可以执行该方法。
   - `native`：表示该方法是本地方法，由其他语言（如 C、C++）实现。

这些修饰符的顺序通常是：访问权限修饰符在前，然后按照 `abstract`、`static`、`final`、`synchronized`、`native` 的顺序书写。但需要注意的是，`abstract` 与 `final`、`static` 不能同时修饰同一个方法，因为 `abstract` 方法需要子类实现，而 `final` 方法不能被重写，`static` 方法属于类本身，不能被子类重写（也就不存在实现的概念）。

3. **返回值类型**：方法执行后返回的数据类型，如果方法不返回任何值，则使用 `void`。
4. **方法名**：遵循 Java 的命名规范，通常采用驼峰命名法，第一个单词首字母小写，后续单词首字母大写。
5. **参数列表**：用括号括起来，参数之间用逗号分隔，定义方法接受的参数及其类型。
6. **泛型声明（`<>`）**：如果方法是泛型方法，在方法名之前声明泛型类型参数，例如 `<T, U>`。泛型声明要放在修饰符和返回值类型之间。

#### 继承和接口

| 比较项             | 继承                                                         | 接口                                                         |
| ------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **定义**           | 一个类（子类）可以继承另一个类（父类）的属性和方法，子类自动拥有父类非私有成员 | 是一种特殊的抽象类型，它定义了一组方法签名，但不包含方法的实现 |
| **实现方式**       | 使用 `extends` 关键字实现，如 `class Child extends Parent`   | 使用 `implements` 关键字实现，一个类可以实现多个接口，如 `class MyClass implements Interface1, Interface2` |
| **继承个数**       | 一个子类只能继承一个父类，单一继承性                         | 一个类可以实现多个接口，允许多重实现                         |
| **成员内容**       | <li>父类可以包含属性（成员变量）、方法（包括抽象方法和具体方法）、构造函数等。</li><li>子类继承父类后，可重写父类的非 `final` 方法。</li> | <li>接口中只能包含抽象方法（Java 8 及以后可包含默认方法和静态方法）、常量（默认 `public static final`）。</li><li>实现接口的类必须实现接口中的所有抽象方法（除非该类也是抽象类）。</li> |
| **访问修饰符**     | 父类成员可以使用各种访问修饰符（`public`、`protected`、`private` 及默认），子类继承后受相应访问规则限制 | 接口中的方法默认是 `public abstract`，常量默认是 `public static final`，不能使用其他访问修饰符修改这些默认属性 |
| **目的**           | <li>实现代码复用，减少重复代码。</li><li>体现类之间的 “is - a” 关系，如 `Dog` 类继承 `Animal` 类，表示狗是一种动物。</li> | <li>用于实现多态和定义一组相关行为的规范，不关心具体实现，体现 “like - a” 关系，如一个类实现 `Serializable` 接口，表示它像可序列化的对象一样能被序列化。</li><li>解决 Java 单继承的局限性，使一个类能具备多种行为。</li> |
| **应用场景**       | <li>当多个类具有共同属性和行为，且存在明显的父子关系时使用继承。</li><li>例如，`Car`、`Truck` 等类可继承 `Vehicle` 类，继承其通用的属性和行为，如轮子数量、速度等。</li> | <li>当需要为不同类提供统一的行为定义，或者希望一个类具备多种不同类型的行为时使用接口。</li><li>例如，`Bird` 类和 `Plane` 类都可以实现 `Flyable` 接口，具备飞行的行为。</li> |
| **对类设计的影响** | 继承会增加类之间的耦合度，父类的修改可能影响子类             | 接口降低了类之间的耦合度，实现接口的类只需关注接口定义的行为，不依赖于其他实现类 |

#### String、StringBuffer、StringBuilder

| 比较项         | String                                                       | StringBuffer                                                 | StringBuilder                                                |
| -------------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **可变性**     | 不可变，一旦创建，其内容不能被修改。对`String`对象的任何修改操作，如拼接、替换等，都会返回一个新的`String`对象 | 可变，`StringBuffer`对象的内容可以在原对象上进行修改，不会创建新的对象 | 可变，`StringBuilder`对象的内容同样可以在原对象上进行修改，不会创建新的对象 |
| **线程安全性** | 线程安全，`String`对象是不可变的，多个线程同时访问时不会出现数据不一致问题 | 线程安全，`StringBuffer`的方法大多使用`synchronized`关键字修饰，确保在多线程环境下的安全访问 | 线程不安全，`StringBuilder`没有使用`synchronized`关键字修饰，在多线程环境下可能出现数据不一致问题 |
| **性能**       | 由于每次修改`String`都会创建新对象，在频繁修改字符串的场景下，性能较差 | 在多线程环境下，由于`synchronized`关键字的存在，会带来一定的性能开销，但在单线程下也能正常工作，性能比`String`在频繁修改场景下好 | 在单线程环境下，性能最佳，因为没有同步机制的开销，适用于字符串频繁修改的场景 |
| **适用场景**   | 适用于字符串内容相对固定，不经常修改的场景，如配置文件中的常量、文本显示等 | 适用于多线程环境下，需要对字符串进行频繁修改的场景，如多线程日志记录等 | 适用于单线程环境下，对字符串进行频繁修改的场景，如大量文本处理、SQL 语句拼接等 |
| **方法特点**   | 提供了丰富的字符串处理方法，如查找子字符串（`indexOf`）、替换字符（`replace`）、分割字符串（`split`）、字符串比较（`equals`、`compareTo`）等 | 除了与`String`类似的字符串处理方法外，还提供了一些可在原对象上修改的方法，如`append`（用于追加字符或字符串）、`insert`（用于插入字符或字符串）等 | 与`StringBuffer`类似，提供了丰富的在原对象上修改字符串的方法 |
| **初始容量**   | 创建`String`对象时，无需指定容量                             | `StringBuffer`有默认初始容量（16 个字符），也可在构造函数中指定初始容量。如果字符串长度超过容量，会自动扩容 | `StringBuilder`同样有默认初始容量（16 个字符），也可在构造函数中指定初始容量。如果字符串长度超过容量，会自动扩容 |

#### 泛型的好处

1. 提高类型的安全性
2. 消除强制类型转换
3. 提高代码的复用性
4. 拥有更高的运行效率

#### Collection、List、Set、Map

| 比较项               | Collection                                            | List                                                         | Set                                                      | Map                                                          |
| -------------------- | ----------------------------------------------------- | ------------------------------------------------------------ | -------------------------------------------------------- | ------------------------------------------------------------ |
| **接口关系**         | 是 `List` 和 `Set` 的父接口，定义了集合操作的通用方法 | 继承自 `Collection` 接口，有序且允许元素重复                 | 继承自 `Collection` 接口，无序且不允许元素重复           | 是一个独立的接口，与 `Collection` 没有继承关系，用于存储键值对 |
| **元素特点**         | 代表一组对象，是集合框架的基础接口                    | 有序，即元素的存储顺序和插入顺序一致。允许包含重复元素       | 无序，元素在集合中的位置没有特定顺序。不允许包含重复元素 | 存储键值对（key - value pairs），一个键最多映射到一个值，键不允许重复 |
| **常用实现类**       | -                                                     | `ArrayList`、`LinkedList`、`Vector`                          | `HashSet`、`TreeSet`、`LinkedHashSet`                    | `HashMap`、`TreeMap`、`HashTable`、`ConcurrentHashMap`       |
| **遍历方式**         | 可以通过 `Iterator` 迭代器遍历                        | 除了使用 `Iterator` 迭代器，还可以通过索引（如 `for` 循环根据索引访问元素）遍历 | 主要通过 `Iterator` 迭代器遍历                           | 可以通过 `keySet()` 获取键的集合，使用 `Iterator` 遍历键，进而获取对应的值；也可以通过 `entrySet()` 获取键值对集合，使用 `Iterator` 遍历；Java 8 后还可以通过 `forEach` 方法遍历 |
| **是否支持随机访问** | 部分实现类支持（如 `ArrayList`）                      | `ArrayList` 支持高效的随机访问，`LinkedList` 随机访问效率较低 | 不支持高效的随机访问，因为无序                           | 不支持随机访问                                               |
| **线程安全性**       | 通常非线程安全                                        | `ArrayList` 和 `LinkedList` 非线程安全；`Vector` 线程安全，但由于同步机制会影响性能 | 通常非线程安全                                           | `HashMap` 非线程安全；`HashTable` 线程安全，但性能较低；`ConcurrentHashMap` 线程安全且性能较好 |

#### HashSet和TreeSet

| 比较项                               | HashSet                                                      | TreeSet                                                      |
| ------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **继承与实现**                       | 继承自`AbstractSet`类，实现`Set`接口                         | 继承自`AbstractSet`类，实现`NavigableSet`接口，进而实现`Set`接口 |
| **元素顺序**                         | 无序，元素插入的顺序与存储顺序无关                           | 有序，默认按照元素的自然顺序（如数字升序、字母表顺序等）排序，也可通过构造函数传入`Comparator`自定义排序规则 |
| **索引**                             | 无索引                                                       | 无索引                                                       |
| **元素唯一性判断**                   | 通过元素的`hashCode()`和`equals()`方法判断元素是否重复。先比较`hashCode`，如果`hashCode`相同再比较`equals` | 通过元素的自然顺序或者传入的`Comparator`比较结果判断元素是否重复。如果两个元素比较结果为 0，则认为是重复元素 |
| **底层数据结构**                     | 基于`HashMap`实现，实际是使用`HashMap`来存储元素，元素作为`HashMap`的键，值是一个固定的`PRESENT`对象 | 基于红黑树（一种自平衡的二叉查找树）实现                     |
| **添加 / 删除 / 查找操作时间复杂度** | 添加、删除和查找操作平均时间复杂度为 O (1)，在哈希冲突严重时，时间复杂度会趋近于 O (n)，n 为元素个数 | 添加、删除和查找操作时间复杂度为 O (log n)，n 为元素个数     |
| **是否允许`null`值**                 | 允许一个`null`值，因为`HashMap`允许一个`null`键              | 不允许`null`值，因为在使用自然顺序或自定义比较器时，`null`无法进行比较 |
| **适用场景**                         | 适用于需要快速判断元素是否存在，对元素顺序无要求的场景，例如检查集合中是否包含某个元素 | 适用于需要对元素进行排序，并且需要按照排序后的顺序进行查找、遍历等操作的场景，例如对学生成绩进行排序并查询特定成绩区间的学生 |

#### ArrayList和LinkedList

| 比较项             | ArrayList                                                    | LinkedList                                                   |
| ------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **数据结构**       | 基于动态数组实现，在内存中是连续存储的                       | 基于双向链表实现，节点在内存中不连续存储                     |
| **随机访问**       | 支持高效的随机访问，通过索引直接定位元素，时间复杂度为 O (1)例如：`list.get(index)` | 随机访问效率较低，需要从链表头或尾开始遍历，时间复杂度为 O (n)例如：若要获取中间某个元素，需从头开始逐个移动指针 |
| **插入和删除操作** | 在列表末尾插入或删除元素效率较高，时间复杂度为 O (1)。但在列表中间插入或删除元素时，需要移动大量元素，时间复杂度为 O (n)，因为涉及元素的移位操作 | 在链表任何位置插入或删除元素效率都较高，时间复杂度为 O (1)，只需修改相邻节点的指针即可 |
| **内存占用**       | 由于是数组结构，除了存储元素本身，额外内存开销较小，主要用于数组扩容预留空间 | 每个节点除了存储元素，还需额外存储前驱和后继节点的引用，因此内存占用相对较大 |
| **遍历方式**       | 支持通过索引遍历，如 `for` 循环；也支持使用迭代器遍历        | 主要通过迭代器遍历，虽然也可以通过索引遍历，但效率低；还支持双向遍历，因为是双向链表 |
| **线程安全性**     | 非线程安全，在多线程环境下需要手动同步                       | 非线程安全，在多线程环境下需要手动同步                       |
| **适用场景**       | 适用于需要频繁随机访问元素的场景，如查找操作较多的情况；也适用于数据量相对固定，插入和删除操作主要在末尾进行的场景 | 适用于需要频繁插入和删除元素的场景，如数据经常变动且需要在任意位置进行增删；还适用于需要双向遍历数据的场景 |
